# 쇼핑몰 프로젝트 진행 계획

작성: 박지호

## 1. 과제의 목표

> 상품 목록에서 장바구니 담기 → **헤더의 숫자가 바뀐다** → **새로고침해도 유지된다**

- **버튼과 결과가 표시되는 곳이 서로 떨어져 있다** — 버튼이 데이터를 바꾸고, 그 데이터를 보고 있던 다른 영역이 따라와야 하는 구조
- **데이터가 화면보다 오래 산다** — 새로고침하면 화면은 다시 그려지지만 장바구니 내용은 남아야 함

페이지 수를 늘리기보다 이 두 가지를 제대로 다루는 쪽으로 범위를 잡는다.

---

## 2. 진행 방식

- **태스크 하나 = 커밋 하나.** 각 태스크에 "무엇을 보면 완료인지"를 함께 적는다.
- 각 마일스톤에 **이번에 사용하는 문법**을 표시한다.

---

## 3. 전체 순서

| | 마일스톤 | 목표 |
|---|---|---|
| M0 | 프로젝트 셋업 | 실행 환경, Git |
| M1 | 상품 목록 | API 데이터를 화면에 그리기 |
| M2 | 담기 + 헤더 뱃지 | **떨어진 두 영역이 같은 데이터를 보게 하기** |
| M3 | 저장소 비교 + 유지 | **데이터 영속화 / 저장소 선택 기준 익히기** |

| M5 | 상태 중심으로 재구성 | 구조 개선 + 검색/필터/정렬 |
| M6 | 정리 | 파일 분리, Vite, 회고 |


### 범위에서 제외한 것

| 제외한 것 | 이유 |
|---|---|
| 상품 상세 페이지 | 페이지 수보다 핵심 기능 구현에 집중한다 |

| 페이지네이션 / 무한 스크롤 | M5의 검색·필터·정렬로 목록 제어를 충분히 다룬다 |

| 1-11 | 반응형 적용 | 모바일 폭에서 정상 |

**확인 질문 (1-4d)** — 강의 복습 후 스스로 답해본다. 막히면 다시 본다.

1. `await` 없이 `fetch`를 호출하면 무엇이 반환되는가?
2. `await`는 왜 `async` 함수 안에서만 쓸 수 있는가?
3. `.then()` 체이닝과 `async`/`await`는 동작이 같은가, 다른가?

> 1-6은 두 방식을 모두 작성한다. 같은 동작을 두 문법으로 써보면 `async`/`await`가 무엇을 감춰주는지 드러난다.

> **1-3b는 데이터 출처와 무관하다.** `createProductCard()`가 돌려주는 것은 완성된 HTML 문자열이므로,
> 그 값이 연습용 객체에서 왔든 서버 응답에서 왔든 화면에 꽂는 방법은 같다.
> API 연결 전에 화면 렌더링을 먼저 완성해 '데이터 받아오기'와 '화면에 그리기'를 분리해서 익힌다. (멘토 제안)

> **1-4는 코딩이 아니라 읽고 이해하는 묶음이다.** 멘토 피드백(2026-10-16)을 반영해 범위를 넓혔다.
> `defer`/`async` → 동기·비동기 → 이벤트 루프는 같은 주제를 현상·개념·원리 세 층위에서 보는 것이므로 위에서부터 내려간다.
> 이벤트 루프는 M3에서 비동기 때문에 헷갈리는 상황을 만난 뒤에 다룬다.

### M5 — 상태 중심으로 재구성

**사용 문법**: `Object.assign`/스프레드, 고차 함수, `filter`→`sort`→`map` 체이닝

새 기능 추가가 아니라 구조를 바꾸는 단계다.

| # | 태스크 | 완료 확인 |
|---|---|---|
| 5-1 | 흩어진 변수를 `state` 객체 하나로 통합 | 전역 변수 정리 |
| 5-2 | `setState(patch)` 작성 — 갱신 후 `render()` 호출 | 한 번 호출로 화면 일치 |
| 5-3 | 기존 코드를 `setState` 방식으로 교체 | 동작 동일 |
| 5-4 | 검색창 추가 | 입력 시 목록 필터링 |
| 5-5 | 카테고리 필터 | 선택 시 해당 상품만 |
| 5-6 | 가격 정렬 | 순서 변경 |
| 5-7 | 세 조건 동시 적용 확인 | 검색+카테고리+정렬 조합 동작 ✅ |
| 5-8 | 결과 없음 화면 | "검색 결과가 없습니다" |

```js
const state = {
  products: [],
  cart: [],
  keyword: '',
  category: 'all',
  sort: 'default',
};

function setState(patch) {
  Object.assign(state, patch);
  saveCart();
  render();
}
```
