## 보여드릴 것

**① 화면 시연** — 세 가지 상태

1. 정상 — dummyjson에서 받아온 상품 목록
2. Slow 4G로 새로고침 → 로딩 표시
3. URL 오타 → 에러 화면 (페이지가 죽지 않음)

**② `main.js`** — 3단 구조

1. `createProductCard` — 상품 객체를 받아 카드 HTML 문자열을 돌려준다
2. `loadProducts` — API를 호출하고 응답을 두 번 벗긴 뒤 상품 배열을 반환한다. `response.ok`가 아니면 `throw`
3. `render` — 로딩 표시 → 배열을 `map`으로 카드 HTML로 바꾸고 `join`으로 합쳐 삽입. `try`/`catch`로 에러 화면 처리

**③ `docs/NOTES.md`** — 특히 1-12 참조/값 부분 (지난 회차 숙제)

## 질문 / 논의 (리뷰 중 작성)

### ① 함수를 더 잘게 쪼개야 할까 ✅

**답변**: createProductCard, loadProducts, render 함수에서 더 잘게 쪼갤 필요는 없어보인다.
다만 실무에서는 API 호출을 위한 전용 함수를 만들기도 하는데, loadProducts(매개변수)와 같이 호출하여 인자를 전달하여 사용하기도 한다.

```js
// 상품 API 호출
async function loadProducts() {
    const response = await fetch("https://dummyjson.com/products");

    if (!response.ok) {
        throw new Error(`상품 목록 요청 실패 (${response.status})`);
    }

    const data = await response.json();
    return data["products"];
}

// 상품 렌더링
async function render() {
    productList.innerHTML = `<li class="product-list__loading">불러오는 중...</li>`;
    try {
        const products = await loadProducts();

        // join("")을 빼면 배열이 문자열로 변환될 때 쉼표가 들어간다.
        productList.innerHTML = products.map((product) => createProductCard(product)).join("");
    } catch (error) {
        console.error(error);
        productList.innerHTML = `<li class="product-list__error">상품 리스트를 불러올 수 없습니다.</li>`;
    }
}
render();
```

함수를 작성할 때는 역할별로 나누면 재활용에 용이하며, 다른 곳에 미치는 영향을 최소화 할 수 있다.
