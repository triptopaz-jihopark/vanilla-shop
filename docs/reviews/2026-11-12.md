### 이번에 파악한 것 — 퍼블과 개발의 역할 분담

마이페이지 탭에 "찜"을 추가하면서, **같은 탭 목록이 두 곳에 존재**한다는 것을 알게 됐다.

| | 위치 | 형태 |
| --- | ---- | ---- |
| 퍼블 | 마이페이지 HTML 8개 파일 | 각 파일에 탭 마크업이 들어 있음 |
| 개발 | `MyPageTab` ViewComponent | `switch`문으로 한 곳에서 관리 |

정적 HTML에는 include가 없으니 **각 파일이 완결된 화면**이어야 하고, 중복은 구조상 불가피하다. 공통화는 ViewComponent가 있는 개발 단계에서 이뤄진다.

**퍼블 산출물 = 완성된 화면 한 장, 개발 = 그 화면을 재사용 단위로 쪼갠 것.**

그리고 퍼블에서 쓰던 `<!-- s: tab -->` / `<!-- e: tab -->` 주석이 사실상 **컴포넌트 경계 표시**였다.

```
퍼블 주석                     개발 컴포넌트
<!-- s: tab -->      ───→    MyPageTab
<!-- s: HEADER -->   ───→    Top
```

앞으로 퍼블할 때 **"이 조각에서 뭐가 변하는가"**를 의식해두면 개발 이식이 수월해진다. `MyPageTab`이 `activeTab` 하나만 받는 이유가 탭에서 변하는 것이 `class="on"` 위치뿐이기 때문이다.

### 리뷰 내용

**① 화면 시연** — 같은 상품을 여러 번 담아도 헤더 숫자는 1, 다른 상품을 담으면 2

**② 클릭 핸들러**

```js
const productId = Number(clicked.dataset.id);
const product = products.find((p) => p.id === productId);
const cartItem = cart.find((item) => item.id === productId);

if (cartItem) {
    cartItem.quantity += 1;
} else {
    cart.push({ ...product, quantity: 1 });
}
updateCartCount();
```

**③ `docs/NOTES.md`** — M2-7 참조 분리 부분

### 판단한 부분

**비교를 `id`로 한 이유.** 처음에는 객체끼리 `===`로 비교했다. 그 시점에는 `cart`에 원본 주소를 그대로 넣고 있어서 동작했지만, 아래에서 복사본을 넣기 시작하면 서로 다른 객체가 되어 영원히 못 찾는다. **주소가 달라져도 유지되는 기준이 `id`**라서 바꿨다.

**복사본을 넣은 이유.** 원래는 `cart.push(product)`였다. 확인해보니 `cart`에 들어간 상품과 `products` 안의 상품이 같은 객체였고(`===`가 `true`), 그대로 두면 장바구니 수량을 올릴 때 상품 목록 원본까지 오염된다.

**수량 증가는 다시 넣지 않아도 된다.** `find`가 돌려준 것은 사본이 아니라 `cart` 안의 그 객체 자체라서, `cartItem.quantity += 1`만으로 반영된다. **같은 참조라는 성질을 한쪽에서는 끊고 한쪽에서는 활용한 셈이다.**

### 겪은 것 — `quantity`가 `NaN`

수량 증가를 먼저 만들고 복사를 미뤄둔 상태에서 같은 상품을 두 번 담았더니 `NaN`이 나왔다.

```js
cart.push(product);        // quantity 없는 원본을 그대로 넣음
cartItem.quantity += 1;    // undefined + 1  →  NaN
```

**에러가 나지 않고 숫자만 조용히 틀리는** 종류였다. 복사본에 `quantity: 1`을 붙이면서 함께 해결됐다. 수량 증가와 복사가 한 쌍이었다.

### 어디까지 분리되었나

전개 구문은 **한 겹만** 복사한다.

```js
cart[0] === products에서 찾은 상품                  // false  ← 겉은 분리
cart[0].reviews === 그 상품의 reviews               // true   ← 속은 공유
```

`images` · `reviews` · `tags` 같은 참조 타입은 여전히 주소를 공유한다. **읽기만 하므로 지금은 문제가 되지 않지만**, 수정하는 순간 드러난다. M3에서 저장할 필드를 추릴 때 다시 볼 부분이다.

### 2-8 뱃지 기준 — 상품 종류 수로 결정

실제 서비스를 확인해보니 뱃지에 종류 수를 쓰고 수량은 장바구니 상세에서 품목별로 보여주고 있었다. **뱃지 숫자와 장바구니를 열었을 때 보이는 줄 수가 일치한다**는 점이 판단 근거다.

`cart.length`가 이미 항목 개수라 코드 변경은 없었고, **판단 근거를 주석으로 남겼다.**
